## 3. #4 — k 비단조성 (반드시 가장 먼저 실행)

#6, #12 가 #4 산출물을 재사용하므로 **순서상 #4 → #6, #12 → 나머지** 가 효율적입니다.

### 3.1 run config 생성

```sh
python scripts/generate_config.py \
    --problem 4 --run-name p4_full \
    --model-profile my_model --db-profile my_db
```

생성물:

- `configs/runs/p4_full.yaml` (problem 4 sweep 정의)
- `configs/generated/p4_full_configuration.yml` (working copy — 사용자 원본 절대 비변경, `MemMachine_변경사항_문서_claude_0427.md` C5)

### 3.2 전체 파이프라인 실행

```sh
python scripts/run_pipeline.py --config configs/runs/p4_full.yaml --stage all
```

내부 5단계 (`MemMachine_변경사항_문서_claude_0427.md` C2):

1. `ingest` → `results/p4_full/ingest.jsonl` (마지막 row `status=ok` 면 다음 실행 시 자동 skip)
2. `retrieve` → `results/p4_full/retrieve.jsonl` (질문별 chunks/perf/token/fact_hits)
3. `generate` → `results/p4_full/generate.jsonl`
4. `judge` → `results/p4_full/judge.jsonl` (+ `llm_score`)
5. `analyze` → `results/p4_full/analyze.json`

### 3.3 결과 위치

```sh
ls results/p4_full/
cat results/p4_full/analyze.json | jq .cells
```

각 cell 에 `search_limit`, `accuracy`, `accuracy_std`, per-category score 가 포함됩니다.

### 3.4 판정 기준 (`MemMachine_재현평가_설계_0425.md` §2 #4)

- **성공**: k 를 늘리는 동안 정확도 상승 둔화·꺾임이 결합 σ 2배 초과
- **부분**: σ 1~2배
- **실패**: k 무관 또는 비례 단조 증가

⚠️ `n_runs=1` 만 지원하므로 σ×2 자동 판정은 미구현 → analyze 출력의 raw 값을 수기 비교 (`MemMachine_재현평가_설계_0425.md` §3.5).

### 3.5 자주 막히는 지점

- chunk = on, prefix = on 이 `fixed` 로 박혀 있음 (`configs/problems/p4.yaml:18-20`). chunk on/off 비교는 **별도 run_name + 별도 ingest** 필요 (`docs/USAGE.md` §3 #4 주의 박스).

- 실패: MS 가 다른 카테고리와 비슷하거나 더 높음


산출 (cell 별, `search_limit` 오름차순):

- 실패: 고 k 에서 accuracy 가 선형 증가

## 11. 정리 — 4-step 체크리스트

1. **사전 준비**: profile 2개 작성 (`my_model.yaml`, `my_db.yaml`), Postgres+Neo4j+LLM 가용 확인, smoke test 통과 (§1).
2. **#4 먼저**: `p4_full` 로 `--stage all` → `results/p4_full/analyze.json` 확보 (§3).
3. **#4 산출 재사용**: `p6_from_p4`, `p12_from_p4` 로 `--stage analyze --decompose-multisession` / `--pareto` 두 줄 (§4, §5).
4. **나머지 단독 run**: `p3_full`, `p2_full`, `p5_full` 순서대로 `--stage all` (§6, §7, §8). p2/p5 는 격리 우회 한 번 더 신경 쓸 것.

각 결과의 `analyze.json` 을 §3.4 / §4.3 / §5.3 / §6.4 / §7.4 / §8.4 의 판정 기준에 직접 대입하면 6개 문제 재현 평가가 끝납니다.
