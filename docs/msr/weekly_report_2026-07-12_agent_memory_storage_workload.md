# [신규 과제 방향성] AI 에이전트 메모리 데이터의 스토리지 디바이스 워크로드 연구

*주간 보고 · 2026-07-12*

---

## 무엇을

AI 에이전트가 생성·저장·재사용하는 메모리 데이터(작업 이력, 조직 지식 자산)가 스토리지 디바이스에 만드는 I/O 워크로드를 블록 레벨에서 정량 분석한다. 이를 통해 에이전트 시대의 스토리지 요구사항(접근 패턴, 데이터 수명, 계층화 특성)을 디바이스 관점에서 정의하고, near-data processing 등 디바이스/시스템 기술의 적용 지점을 도출한다.

## 왜

에이전트 확산에 따른 데이터 증가 논의는 KV cache 등 연산 측면에 집중되어 있고, 에이전트가 만들어내는 영구 저장 데이터가 스토리지에 주는 부하는 규명되지 않았다. Microsoft가 Build 2026에서 agent memory를 관리형 서비스로 출시(Foundry Agent Memory: session/user/procedural scope, TTL 관리)하는 등 상위 서비스 레이어는 빠르게 상용화 중이나, 그 아래 스토리지 계층의 워크로드 특성은 공개된 바 없다. 시스템 관점 분석 논문이 2026년 6월에야 등장했으며(arXiv:2606.06448 — 단일 에이전트, 애플리케이션 레벨 비용 분석에 한정), 디바이스 레벨 I/O 분석은 공백으로 파악된다. SSD 업체로서 이 워크로드의 디바이스 요구사항을 선제 정의할 수 있는 시점이다.

## 어떻게

**① [워크로드 모델링]** 에이전트가 메모리를 생성·탐색·갱신하는 워크로드를 모델링한다. 최근 공개된 에이전트 실사용 트레이스와 자체 에이전트 메모리 인프라(기존 MemMachine 평가 환경) 실측을 결합해, 멀티 에이전트·공유/개인 메모리 구조를 반영한 모델을 실데이터 기반으로 캘리브레이션한다.

**② [공백 검증]** 정의된 워크로드를 기준으로 기존 벤치마크·연구가 이를 재현/분석 가능한지 검증한다. 기존 도구는 단일 클라이언트·정적 데이터 전제이거나 정확도 중심으로 파악되며, 이 검증으로 본 과제의 차별점(멀티 에이전트 동시성 하의 디바이스 레벨 I/O)을 확정한다.

**③ [측정 체계 구축]** 워크로드 모델을 구동하며 vector DB·graph DB 하단의 블록 레벨 I/O를 계측하는 체계를 구축한다. 메모리 캐시로 인해 디바이스 I/O가 관측되지 않는 문제를 데이터 규모 확장·buffer pool 제한으로 통제한다.

**④ [분석·도출]** 에이전트 수 스케일에 따른 디바이스 병목과 계층화 지표(데이터 수명, 재사용 패턴)를 도출한다. 지표는 특정 media에 종속되지 않게 설계하여 CSD 외 신규 media 검토에도 참조 가능하도록 한다.

### ① 캘리브레이션에 활용할 공개 실사용 트레이스

- **TraceLab** (arXiv:2606.30560, 2026.06): Claude Code·Codex 실사용 트레이스 — 43명 개발자 8개월, 약 4,300세션 / 35만 LLM step / 43만 tool call. 데이터셋·수집 파이프라인·분석 코드 공개. 에이전트 세션 구조와 tool call 패턴의 캘리브레이션 소스
- **BurstGPT** (KDD 2025): Azure OpenAI 실서비스 트레이스 — 213일간 1,031만 건. 사용자 동시성·burstiness, 대화 내 요청 수·간격 포함. 멀티 유저 동시성 패턴의 캘리브레이션 소스
- 단, 두 트레이스 모두 LLM serving 관점(토큰·요청 수준) 데이터로, 메모리 저장/탐색 워크로드로의 변환 매핑은 본 과제에서 설계

## 산출물

시스템/스토리지 학회 논문(2027년 상반기 투고 목표), 디바이스 요구사항 정의 리포트, near-data processing 후속 연구 연계.
