# 발명 제안서 — 검색 결과를 질문마다 알맞게 잘라 쓰는 적응형 문맥 선택 (자동 bias 조절)

> 이 문서는 **변리사 재작성을 위한 아이디어 제안서**입니다. 정식 청구항·명세서가 아니라, 발명의 핵심과 동작을 쉽게 설명하는 것을 목적으로 합니다.
> (상세 청구 구조·출원 유의사항은 별도 문서 `invention_disclosure_adaptive_k_bias_auto.md` 참고)

---

## 1. 발명요지

AI 에이전트는 질문에 답하기 위해 **메모리(기억) 저장소에서 관련 정보를 검색**한다. 이때 검색 엔진은 후보를 여러 개 찾아 각각 관련도 점수를 매기는데, 그중 **실제로 답변에 넣을 것을 몇 개나 쓸지**를 정해야 한다. 너무 많이 쓰면 토큰·연산·저장장치 부하가 늘고 엉뚱한 정보(노이즈)가 섞이며, 너무 적게 쓰면 정작 필요한 근거를 놓친다. 적정 개수는 질문마다 다르다.

본 발명은 이 "몇 개를 쓸지"를 **질문마다 자동으로 정하는 방법**이다. 핵심은 두 가지다.

- **(A) 위치 가중을 곱한 낙폭 컷** — 점수가 크게 떨어지는(낙폭이 큰) 지점에서 자르되, 자르는 위치가 뒤쪽일수록 조금 더 유리하게 **곱셈으로 가중**을 준다. 이 가중의 세기를 `bias`라는 하나의 값으로 조절한다. `bias`를 키우면 더 넉넉히(많이) 남기고, 0으로 두면 기존의 "가장 큰 낙폭에서 자르기"와 똑같아진다.
- **(B) bias 자동 조절** — 이 `bias` 값을 사람이 손으로 정하지 않고, **점수 분포 모양·목표 예산·답변 품질** 중 하나(또는 조합)를 보고 자동으로 정한다.

즉, "낙폭 + 위치"를 **곱셈으로 결합**한 단순한 컷 방식(A)에, 그 세기를 **스스로 맞추는 자동 조절(B)**을 얹은 것이 본 발명이다.

**효과는 두 가지다.** 첫째, 질문마다 필요한 근거를 놓치지 않고 남겨 **정확도**를 유지·향상한다. 둘째, 필요한 만큼만 남기므로 **LLM에 넣는 문맥 토큰이 줄어 추론 비용·지연이 감소**한다 — 실제 측정에서도 **약 10%의 토큰 감소**를 확인했다. 두 이점을 `bias`와 그 자동 조절로 **동시에** 달성하는 것이 특징이다.

## 2. 기존 문제점

**(1) 고정 개수(top-k)의 한계.** 대부분의 검색은 "상위 몇 개"를 미리 정해 놓고 자른다. 하지만 쉬운 질문은 1~2개면 충분하고, 여러 근거를 엮어야 하는 질문은 훨씬 많이 필요하다. 고정값은 이 차이를 반영하지 못해 낭비 아니면 근거 부족이 된다.

**(2) "가장 큰 낙폭에서 자르기"의 한계.** 최근 방법(Adaptive-k)은 점수를 내림차순으로 늘어놓고 **점수가 가장 크게 뚝 떨어지는 한 지점**에서 자른다. 학습이나 튜닝이 필요 없다는 장점이 있지만, 그 **단 하나의 낙폭만** 보기 때문에

- 검색 엔진이 1등에 점수를 몰아주면 **1개만 남기는 과소 선택**이 되고,
- 점수가 완만하게 줄어드는(여러 근거가 비슷하게 중요한) 질문에서는 **근거가 부족**해진다.

**(3) 위치를 고려한 방법(CAR)의 부담.** 낙폭에 더해 "자르는 위치"까지 고려하는 방법(CAR)도 있으나, 후보들을 먼저 **군집화(클러스터링)** 해야 하고 그에 딸린 하이퍼파라미터 탐색이 필요해 무겁다. 또한 위치를 **덧셈으로** 반영하는 탓에, 낙폭이 거의 없는 밋밋한 지점도 위치 점수만으로 잘릴 수 있다(뒤에서 비교).

## 3. 해결방법

**핵심 아이디어(A): "낙폭 × 위치가중".** 각 후보 사이의 낙폭에, 위치가 뒤로 갈수록 커지는 가중치를 **곱한다**. 가중치는 `k^bias`(k는 자르는 위치 순번) 형태로 두어, 하나의 값 `bias`로 세기를 조절한다.

- `bias = 0` → 가중치가 항상 1 → **기존 "가장 큰 낙폭에서 자르기"와 동일**(안전한 하위호환).
- `bias`가 커질수록 → 뒤쪽 위치가 유리해져 → **더 많이 남긴다(근거 확보)**.
- **곱셈이라는 점이 중요**하다. 낙폭이 0에 가까운 지점은 위치가 아무리 뒤여도 (0을 곱하니) 절대 선택되지 않는다. 즉 **자르는 자리는 항상 "진짜 낙폭이 있는 곳"**이고, 위치는 그 진짜 낙폭들 사이에서 우선순위만 바꾼다.

**자동 조절(B): bias를 스스로 정하기.** 아래 세 방식 중 하나 이상을 사용한다.

1. **점수 모양 보고 정하기 (질문별, 추가 비용 거의 0).** 점수가 어느 한 곳에서 **뚝 떨어지는 절벽이 뚜렷하면** 그 절벽을 믿고 `bias`를 낮춰 적게 남긴다. 반대로 점수가 **비슷비슷해 어디서 잘라야 할지 애매하면** `bias`를 높여 넉넉히 남긴다. 이미 계산해 둔 낙폭 값만 보면 되므로 추가 지연이 사실상 없다.
2. **목표 예산에 맞추기 (세션 단위).** "평균적으로 후보 5개쯤(또는 토큰 얼마 이내)만 쓰자"는 목표를 정하면, 최근 결과의 평균을 보고 `bias`를 조금씩 올리고 내려 목표에 자동으로 수렴시킨다.
3. **답변 품질 피드백으로 정하기.** 생성된 답이 **근거를 거의 안 썼거나 부실하면** 다음부터 `bias`를 올려 더 남기고, 반대로 **잔뜩 남겼는데 대부분 안 쓰였으면** 내려서 줄인다.

## 4. 구조 (동작 과정 포함)

**파이프라인 내 위치.** 본 발명은 검색 파이프라인의 맨 끝, "생성 직전"에 놓인다.

```
질문 → (1) 벡터/그래프 DB 검색으로 후보 모으기
     → (2) reranker가 후보마다 관련도 점수 매기기
     → (3) 【본 발명】 점수를 보고 "몇 개 쓸지" 컷 결정
     → (4) 잘라낸 상위 문맥만 LLM에 넣어 답변 생성
```

**동작 과정(단계별).**

1. 후보들을 **관련도 점수 내림차순**으로 정렬한다.
2. 이웃한 점수끼리의 **낙폭(차이)**을 모두 계산한다.
3. (자동 조절을 쓰면) 여기서 **`bias`를 결정**한다 — 점수 모양(절벽이 뚜렷한지) / 목표 예산 / 이전 답변 품질 중 택일.
4. 각 후보 위치 k마다 **점수 = 낙폭 × k^bias** 를 계산한다.
5. 이 값이 **가장 큰 위치에서 자른다.** 그 앞까지를 "쓸 문맥"으로 남긴다.

**참고 구현(핵심부).**

```python
def adaptive_k_cutoff(scores_desc, min_k, max_k, bias=0.0) -> int:
    # scores_desc: 점수 내림차순 리스트
    n = len(scores_desc)
    best_k, best = min(max_k or n, n), -1.0
    for k in range(max(1, min_k), min(max_k or n, n)):
        gap = scores_desc[k - 1] - scores_desc[k]  # 이웃 간 낙폭
        weighted = gap * (k ** bias)               # 핵심: 낙폭 × 위치가중
        if weighted > best:
            best, best_k = weighted, k
    return best_k   # 앞에서부터 best_k개를 유지
```

**동작 예시.**

- *절벽이 뚜렷한 질문* — 점수 `[0.95, 0.60, 0.58, 0.55, 0.52]`
  낙폭은 첫 자리(0.95→0.60=0.35)가 압도적. 자동 조절은 "절벽이 뚜렷하다"고 보고 `bias`를 낮춰 → **1개만 유지**(토큰 절약).
- *밋밋해서 애매한 질문* — 점수 `[0.80, 0.72, 0.65, 0.58, 0.50]`
  낙폭이 다 비슷(약 0.07~0.08). 자동 조절은 "애매하다"고 보고 `bias`를 높여 → **4개 유지**(근거 확보).
  → **같은 알고리즘이 점수 모양만 보고** 절벽형은 1개, 밋밋형은 4개를 자동으로 고른다.

**곱셈이 덧셈과 다른 점(비교 예).** 낙폭이 `[0.50, 0, 0, 0.05]`인 경우(진짜 낙폭은 맨 앞과 맨 뒤 둘뿐):

- 본 발명(곱셈, bias=2): 뒤쪽 작은 낙폭(0.05)에 큰 위치가중(=16)이 곱해져 앞의 큰 낙폭(0.50)을 넘어섬 → **뒤에서 자름(4개 유지)**.
- 위치를 덧셈으로 더하는 방식(CAR류): 위치 점수를 아무리 더해도 앞자리의 큰 낙폭을 못 넘겨 → **앞에서 자름(1개 유지)**.
- → 두 방식은 **결과가 다르며**, 덧셈 방식은 `bias` 같은 손잡이가 없어 이런 조절 자체가 불가능하다.

## 5. 보호받고자 하는 주요 기술 구성

본 발명이 보호받고자 하는 핵심은 **아래 필수 구성의 결합**이며, 선택 구성은 실시 형태에 따라 부가된다.

**[필수 구성]**

| # | 구성 | 역할 |
|---|---|---|
| 1 | 후보·점수 획득부 | 벡터/그래프 DB 검색으로 후보 문맥을 얻고, 관련도 점수를 매겨 내림차순 정렬 |
| 2 | 낙폭 산출부 | 인접 순위 간 점수 낙폭 `g_k = s_k − s_(k+1)` 계산 |
| 3 | **순위 가중 결합부** | 낙폭에 순위가 뒤일수록 커지는 가중 `f(k)`(예: `k^bias`)를 **곱셈**으로 결합 → `g_k·f(k)`. 낙폭이 0이면 0이 되어 **의미 없는 지점은 컷 안 됨(gap-anchored)** |
| 4 | 컷 결정부 | `g_k·f(k)`가 최대인 순위에서 잘라 상위만 유지 |
| 5 | **bias 자동 결정부** | 가중 세기 `bias`를 고정하지 않고 **점수 분포·목표 예산·답변 품질** 중 하나 이상으로 자동 결정해 구성 3에 전달 |
| 6 | 문맥 전달부 | 유지된 문맥만 LLM에 넣어 생성 → 토큰·비용·지연 절감 |

> **보호의 핵심 = 구성 3(곱셈 순위가중·gap-anchored) + 구성 5(bias 자동 결정)의 결합.** 구성 1·2·4·6은 이를 성립시키는 처리 흐름이다.

**[선택 구성] (권리범위 확장)**
가중 함수 `f(k)` 형태 / 낙폭 정의(상대·윈도우·정규화) / 점수 소스(reranker·벡터·그래프·LLM 판정) / bias 결정 신호(분리도·엔트로피·질의유형·신뢰도·예산·품질) / 선택 규칙(최댓값·임계값·누적질량) / 적용 단위(메모리 스코프·멀티에이전트·모달리티별) / 학습형 bias.

**구성도 (블록 다이어그램)**

```
                     질의(Query)
                         │
      ┌──────────────────▼───────────────────┐
      │ [구성1] 후보·점수 획득부                │
      │  벡터/그래프 DB 검색 → 후보 집합         │
      │  관련도 점수 부여 → 내림차순 정렬        │
      └──────────────────┬───────────────────┘
                         │  s_1 ≥ s_2 ≥ … ≥ s_n
             ┌───────────▼───────────┐
             │ [구성2] 낙폭 산출부     │  g_k = s_k − s_(k+1)
             └───────────┬───────────┘
                         │  {g_k}
     ┌───────────────────▼───────────────────┐    ┌────────────────────────────┐
     │ [구성3] 순위 가중 결합부                 │◀─bias─│ [구성5] bias 자동 결정부      │
     │  score_k = g_k · f(k)   (곱셈)          │    │  신호: 점수분포 / 예산 / 품질   │
     │  → 무-낙폭 지점 배제 (gap-anchored)      │    └────────────────────────────┘
     └───────────────────┬───────────────────┘                    ▲
                         │  {score_k}                              │
             ┌───────────▼───────────┐                            │
             │ [구성4] 컷 결정부       │  k* = argmax score_k        │
             │  → 상위 k* 유지         │                            │
             └───────────┬───────────┘                            │
                         │  선택된 문맥                             │
             ┌───────────▼──────────────────┐                     │
             │ [구성6] 문맥 전달부 → LLM 생성  │  토큰↓·비용↓·지연↓    │
             └───────────┬──────────────────┘                     │
                         │                                         │
                    품질 신호(선택) ────────────────────────────────┘
                         (다운스트림 품질 피드백 실시 시)
```

## 6. 기존 연구 대비 차별성

| 구분 | Adaptive-k (Taguchi, 2025) | CAR (2025) | **본 발명** |
|---|---|---|---|
| 자르는 위치 고려 | 안 함 | 함 | 함 |
| 낙폭·위치 결합 방식 | — | **덧셈** | **곱셈** |
| 밋밋한(낙폭 없는) 지점 컷 | (위치 안 봄) | 가능성 있음 | **불가능(항상 진짜 낙폭에서만)** |
| 군집화(클러스터링) 필요 | 불필요 | **필요** | 불필요 |
| 세기 조절 손잡이 | 없음 | 고정 | **연속값 `bias`** |
| bias 자동 조절 | — | — | **점수모양·예산·품질 3방식** |
| 추가 지연 | 낮음 | 군집화 비용 | 거의 0 |

**핵심 차별점 세 가지.**

1. **곱셈으로 결합** → 자르는 자리가 항상 "진짜 낙폭"에 걸린다. 덧셈 방식(CAR)은 밋밋한 곳도 위치 점수만으로 잘릴 수 있어 이 보장이 없다.
2. **군집화가 필요 없다** → CAR은 클러스터링과 그 설정 탐색이 필요하지만, 본 발명은 이미 계산한 낙폭만으로 끝나 가볍고 결정론적이다.
3. **bias를 자동으로 조절한다** → 기존 두 방법 모두 이런 자동 조절 개념이 없다. 이 자동 조절이 본 발명의 가장 뚜렷한 신규점이다.

**효과 측면 (정확도 + 비용).** 필요한 만큼만 남기므로 LLM 입력 문맥이 줄어 **추론 토큰·비용·지연이 감소**한다(실측 **약 10% 토큰 감소**). 다른 적응형 방법도 토큰을 줄이지만, 본 발명은 `bias`와 그 자동 조절로 **정확도–토큰 균형 자체를 조절·자동화**한다는 점이 다르다 — 정확도를 유지·향상하면서 토큰을 줄이는 지점을 스스로 찾는다.

### ※ 검토 유의 (짧게)

- **공개 이력 확인이 최우선**: 곱셈 bias 기본형은 이미 코드로 구현되어 있음(MemMachine, 브랜치 `v0.3.9_msr`). 오픈소스 저장소에 **공개(push)되었는지** 반드시 확인 — 공개 시 신규성에 영향. 출원 전략을 IP팀과 협의.
- §4의 **컷 개수 예시(1개/4개)**는 동작 설명용이다. 한편 **토큰 약 10% 감소는 실측 결과**이므로, 출원 시 **측정 조건(데이터셋·모델·설정)**을 함께 기록해 효과 근거로 삼을 것(정확도 지표도 같은 실험으로 병기 권고).
- 선행조사 시 Adaptive-k·CAR 외에 **knee/elbow 검출(Kneedle), gap statistic** 등 "경계 자동 검출" 계열도 함께 확인 권고.
