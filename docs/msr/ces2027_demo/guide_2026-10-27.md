# CES 2027 MemMachine 비교 데모 사용 가이드

작성일 2026-10-27. 이 문서는 **처음 보는 사람이나 Claude Code 같은 도구가 명령을 하나씩 복사해 붙여 넣으며 끝까지 갈 수 있도록** 쓴 것이다. 왜 이렇게 만들었는지와 근거는 [설계 문서](design_2026-10-26.md)에, Mac에서 이 가이드대로 통과한 기록은 [Mac 검증](verification_mac_2026-10-27.md)에, 부스로 옮기는 순서는 [이전 절차서](relocation_2026-10-27.md)에 있다.

각 단계는 같은 형식이다. **왜** 한 문장, **명령** 복사해 붙여 넣기, **나와야 하는 것**, **다르면** 어떻게 할지. 앞 단계가 통과하기 전에 다음 단계로 가지 않는다. 경로는 모두 저장소의 `tools/ces2027_demo/` 기준이다.

## 0. 이 데모가 하는 일 (3분)

Open WebUI의 모델 비교 화면에서 같은 질문에 두 답을 나란히 보여 준다. 왼쪽 "MemMachine + 모델"은 MemMachine에서 과거 대화를 검색해 그 기억 5개를 먼저 목록으로 보여 주고 답하고, 오른쪽 "모델 (no memory)"는 같은 Pipe를 거쳐 같은 LLM이 기억 없이 답하며, 답 위에 회색 한 줄 "No memory used"를 쓴다. 같은 두 모델의 "(step by step)" 형태로 바꾸면 기억 검색, 프롬프트 구성, LLM 호출의 세 단계를 2초 간격으로 보여 준 뒤 답한다. 과거 대화는 사이드바에 실제 채팅으로 들어 있어 관객이 열어 볼 수 있다.

구성 요소는 다섯 가지다. Open WebUI(화면), MemMachine(기억 서버), PostgreSQL과 Qdrant(기억 저장소), vLLM 두 대(채팅 모델과 임베딩 모델)다. Open WebUI와 MemMachine의 소스는 고치지 않았다. 우리가 만든 것은 Open WebUI 안에서 도는 Pipe 함수 하나, compose 파일 하나, 설정 파일 하나, 스크립트 다섯이다.

| 파일 | 역할 |
|---|---|
| `deploy/docker-compose.yml` | 전체 스택. 프로필 `local`(Mac), `db`, `app`, `llm`, `embed`(부스 서버)로 올릴 것을 고른다 |
| `deploy/.env` | 장소별 값. `.env.example`을 복사해 만든다. 다른 서버의 주소, 공개 포트, 시간대, 모델 이름, vLLM 설정 |
| `deploy/memmachine.yml` | MemMachine 설정. 모든 장소에서 같다. 임베딩 차원 `dimensions`만 모델에 맞춰 한 번 고친다 |
| `pipe/memmachine_pipe.py` | Open WebUI Pipe. 기억 검색, 목록 출력, LLM 호출 |
| `scripts/setup_openwebui.py` | 계정, Pipe 설치, Valve, 두 모델 항목, 계정 설정 |
| `scripts/load_scenario.py` | 대본의 과거 대화를 Open WebUI와 MemMachine에 적재 |
| `scripts/demo_check.py` | 준비 상태 검사. 전원을 켠 뒤 이것 하나만 돌리면 된다 |
| `scripts/demo_reset.sh` | 문제가 생겼을 때 이 서버의 컨테이너를 다시 만들고 세팅, 적재, 검사를 한 번에 한다 |
| `scripts/demo_monitor.py` | 시연 중 상태 표시. 서버 여섯 곳과 컨테이너를 몇 초마다 보여 주고 unhealthy 컨테이너를 다시 시작한다 |
| `scenario/script.json` | 부스 대본. `script.sample.json`은 형식 예시 |
| `mock/` | Mac에서 vLLM 두 대를 대신하는 가짜 서버 |

Claude Code로 이 가이드를 수행한다면 먼저 `README.md`, 이 문서, `deploy/.env.example`, `deploy/docker-compose.yml`을 읽는다. 지켜야 할 것은 네 가지다. Open WebUI와 MemMachine 소스를 고치지 않는다. `deploy/.env`는 커밋하지 않는다(gitignore에 있다). 스크립트는 실행마다 한 번 로그인하므로 3분에 15번을 넘기지 않는다. 적재 도구는 실행할 때마다 채팅을 모두 지우고 새 프로젝트로 다시 넣는다.

## 1. 준비 (10분)

### 1.1 코드 받기

**왜** 스택에 필요한 파일이 모두 브랜치 안에 있다.

```bash
git clone https://github.com/taejin-oh/MemMachine.git
cd MemMachine
git checkout msr_ces2027_demo
cd tools/ces2027_demo
```

**나와야 하는 것** `ls`에 `deploy pipe mock scripts scenario assets README.md`가 보인다.

**다르면** 브랜치 이름을 확인한다. 이미 clone이 있으면 `git pull`로 최신을 받는다.

### 1.2 필요한 프로그램

**왜** compose 프로필과 표준 라이브러리만 쓰는 Python이 전부다.

```bash
docker --version && docker compose version && python3 --version
```

**나와야 하는 것** Docker Compose가 v2(프로필 지원), Python이 3.10 이상이다. GPU 서버에는 추가로 `nvidia-smi`가 동작하고 NVIDIA Container Toolkit이 설치되어 있어야 한다(`docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi`가 GPU를 보여 준다).

**다르면** Docker Desktop이나 Docker Engine 최신판을 설치한다. Python은 가상환경이 필요 없다.

### 1.3 장소별 값 적기

**왜** 장소마다 다른 값은 `.env` 한 파일에만 있다.

```bash
cd deploy
cp .env.example .env
```

Mac이면 예시 값을 그대로 써도 된다(포트 3300과 8380이 쓰이고 있으면 바꾼다). 회사나 부스이면 다음을 고친다.

| 항목 | 고칠 값 |
|---|---|
| `DB_HOST`, `LLM_HOST`, `EMBED_HOST`, `APP_HOST` | 각 서버의 IP. 두 vLLM을 같은 서버에 올리면 `LLM_HOST`와 `EMBED_HOST`가 같다 |
| `OPENWEBUI_PORT`, `MEMMACHINE_PORT` | `3000`, `8080` |
| `TZ` | 시연 화면 장비의 시간대. 부스는 `America/Los_Angeles` |
| `LLM_MODEL_NAME` | 채팅 모델의 서빙 이름. 화면에 이 이름이 보인다. 예: `Qwen3-8B` |
| `LLM_BASE_URLS` | 그대로 `http://llm:8000/v1`. 채팅 모델을 둘 띄우면 `;`로 잇는다 |
| `ADMIN_*`, `BOOTH_*`, `WEBUI_SECRET_KEY` | 스크립트가 쓰는 스태프 계정, 부스 화면이 로그인하는 부스 계정, 비밀 키. 한 번 정하면 바꾸지 않는다 |
| `VLLM_IMAGE`, `LLM_MODEL_PATH`, `EMBED_MODEL_PATH`, `LLM_GPU`, `EMBED_GPU`, `LLM_GPU_MEMORY`, `EMBED_GPU_MEMORY` | GPU 서버의 값. 가중치 디렉터리는 Hugging Face 형식 그대로 |

**나와야 하는 것** `docker compose --profile local config --quiet`(Mac) 또는 `docker compose --profile app config --quiet`(앱 서버)가 아무 말 없이 끝난다.

**다르면** 메시지에 비어 있는 변수 이름이 나온다. `.env`에 그 줄을 채운다.

### 1.4 임베딩 차원 적기 (회사와 부스만)

**왜** MemMachine 설정 파일은 임베딩 차원을 숫자로 가진다. 모델을 바꾸면 기억을 다시 넣어야 하므로 한 번 정하고 고정한다.

`deploy/memmachine.yml`의 `dimensions: 384`를 임베딩 모델의 출력 차원으로 고친다(예: `bge-m3`는 1024). 임베딩 모델의 서빙 이름은 compose가 `embed`로 고정하므로 다른 줄은 손대지 않는다.

**나와야 하는 것** `grep dimensions memmachine.yml`에 새 값이 보인다.

**다르면** 값을 모르면 모델 카드의 `hidden_size` 또는 `embedding dimension`을 본다.

## 2. Mac에서 한 바퀴 (20분)

GPU가 없으므로 vLLM 두 대 대신 mock이 답한다. mock의 답은 기억이 프롬프트에 들어갔는지만 보여 주고, 임베딩은 단어 겹침으로 만든 것이라 의미 검색은 되지 않는다.

### 2.1 스택 올리기

**왜** 컨테이너 다섯 개가 뜨고 서로 연결되는지 본다. 처음에는 MemMachine과 Open WebUI 이미지를 내려받고 mock을 빌드하므로 몇 분 걸린다.

```bash
cd deploy
docker compose --profile local up -d --build --wait
docker compose --profile local ps
```

**나와야 하는 것** `memmachine`, `openwebui`, `postgres`가 `healthy`, `qdrant`와 `mock`이 `Up`.

**다르면** `docker compose --profile local logs <서비스>`를 본다. `memmachine`이 반복해 재시작하면 `postgres`가 아직 안 떴을 때이므로 1분 뒤 다시 본다. `port is already allocated`면 포트 충돌이다. 3300과 8380은 `.env`에서 바꾸고, 5432, 6333, 6334(DB)와 8000, 8001(mock)은 고정이므로 그 포트를 쓰는 프로그램을 멈추거나 compose 파일의 호스트 쪽 포트를 고친다.

### 2.2 Open WebUI 설정

**왜** 계정, Pipe, 두 모델 항목은 환경 변수로 만들 수 없어 관리 API로 넣는다.

```bash
cd ..
python3 scripts/setup_openwebui.py
```

**나와야 하는 것**

```
signed in as staff@demo.local (admin)
function memmachine_pipe: created
function memmachine_pipe: enabled
model memmachine_pipe.mock-llm-a: created as 'MemMachine + mock-llm-a'
model memmachine_pipe.mock-llm-a--no-memory: created as 'mock-llm-a (no memory)'
booth account visitor@demo.local: created
account settings of staff@demo.local: release notes off, personal system prompt empty, new chats temporary
account settings of visitor@demo.local: release notes off, personal system prompt empty, new chats temporary
done
```

두 번째 실행부터는 `created`가 `updated`로, 부스 계정 줄은 `exists`로 바뀐다.

**다르면** `sign-in failed ... HTTP 429`이면 3분 기다린다. `this account is not an admin`이면 다른 계정이 먼저 가입한 것이므로 `docker compose --profile local down -v`로 지우고 2.1부터 다시 한다.

### 2.3 대본 적재

**왜** 과거 대화가 사이드바와 기억에 같은 내용으로 들어가야 한다.

```bash
python3 scripts/load_scenario.py scenario/script.json
```

**나와야 하는 것** `project ces-<날짜>-<시각>: Pipe valve set, previous chats of visitor@demo.local deleted` 다음에 세션 일곱 줄, 마지막에 `done`.

**다르면** `session '...': the date needs a UTC offset`은 대본의 날짜에 `-08:00` 같은 오프셋이 없는 것이다. HTTP 500이면 MemMachine 로그를 본다. 적재는 처음부터 다시 하므로 그냥 다시 실행하면 된다.

### 2.4 검사

**왜** 전원을 켠 뒤 이 명령 하나로 준비 상태를 본다. 여기서 익혀 둔다.

```bash
python3 scripts/demo_check.py scenario/script.json
```

**나와야 하는 것** 모든 줄이 `OK`이고 마지막이 `all checks passed`. Mac에서는 `top-5 memories` 줄이 `WARN`일 수 있다. mock 임베더는 단어 겹침으로만 검색하므로 기대 문구는 실제 임베더에서 확인한다는 뜻이며, 실패로 세지 않는다.

**다르면** `FAIL` 줄의 끝에 이유가 있다. `record mode`가 `FAIL`이면 관리자 화면(Admin Panel > Functions > MemMachine > Valves)에서 `RECORD_MEMORY`를 끈다.

### 2.5 화면으로 확인

**왜** 관객이 보는 것은 화면이다.

브라우저로 `http://127.0.0.1:3300`을 열고 `.env`의 `BOOTH_EMAIL`, `BOOTH_PASSWORD`로 들어간다. 스태프 계정(`ADMIN_*`)은 스크립트용이다. 그 계정으로 들어가면 Open WebUI가 관리자에게는 기능을 숨기지 않아 첨부와 마이크 단추가 그대로 보인다. 사이드바가 접혀 있으면 왼쪽 위 단추로 펼친다.

**나와야 하는 것** 사이드바에 과거 채팅 일곱 개. 새 채팅에 아바타 둘과 "mock-llm-a (no memory)" 이름, 그 위에 "Temporary Chat" 표시(`.env`의 `TEMPORARY_CHAT=true`일 때). 입력창에는 보내기 단추만 있고 첨부, 마이크, 음성 통화, 컨트롤 단추가 없다. 대본의 첫 질문 "Can you plan the menu for Mia's birthday party this Saturday?"를 보내면 왼쪽에 "Retrieved 5 memories"와 파란 NOTE 블록 안의 목록(날짜와 세션 제목, 본문 한 줄) 다음에 답이, 오른쪽에 기억 없는 답이 나온다. New Chat을 누르면 질문 채팅은 사이드바에 남지 않는다. 사이드바의 과거 채팅을 열면 메시지에 마우스를 올렸을 때 대본의 시각이 보인다. 오른쪽 카드는 회색 한 줄 "No memory used"로 시작하고 두 답은 80단어 안팎으로 짧다.

오늘 날짜가 대본 날짜(2026년 11월과 12월)보다 앞서면 사이드바 묶음이 "Previous 7 days"나 "in a month"로 보이고 읽지 않음 점이 찍힌다. 브라우저의 현재 시각 기준이라 그렇고, 시연 날짜(2027년 1월)에는 월별로 묶인다. 미리 보고 싶으면 대본의 날짜를 석 달 당긴 복사본을 적재해 본다.

**다르면** 모델이 하나만 선택되어 있으면 `.env`의 `LLM_MODEL_NAME`과 mock의 모델 이름이 다른 것이다. "Model not found"는 LLM 서버가 켜진 직후 모델 목록이 갱신되지 않은 것이므로 새로 고친다.

### 2.6 지우고 다시 하기

**왜** 처음부터 다시 확인하고 싶을 때.

```bash
cd deploy && docker compose --profile local down -v && cd ..
```

볼륨까지 지워지므로 2.1부터 다시 한다. 대본만 바꿨으면 `load_scenario.py`만 다시 실행하고, Pipe 코드나 `.env`를 바꿨으면 `setup_openwebui.py`를 다시 실행한다(compose 환경 변수를 바꿨으면 그 전에 `docker compose --profile local up -d openwebui`).

## 3. 회사에서 실제 vLLM으로 (반나절)

회사에서 처음 올릴 때는 git clone부터 결과 push까지 한 단계씩 적은 [회사 실행서](company_runbook_2026-10-27.md)를 따르는 것이 더 쉽다. 이 장은 그 요약이다.

서버가 네 대면 각 서버에서, H100 두 장이 한 서버에 있으면 그 서버에서 `llm`과 `embed` 프로필을 함께 올린다. 1장의 준비를 서버마다 한다. 명령은 모두 `tools/ces2027_demo/deploy`에서 실행한다.

### 3.1 DB 서버

```bash
docker compose --profile db up -d --wait
```

**나와야 하는 것** `postgres`가 `healthy`, `qdrant`가 `Up`.

### 3.2 임베더 서버와 LLM 서버

```bash
docker compose --profile embed up -d
docker compose --profile llm up -d
docker compose ps
```

**나와야 하는 것** 몇 분 뒤 둘 다 `healthy`. `curl http://localhost:8001/v1/models`에 `embed`, `curl http://localhost:8000/v1/models`에 `.env`의 `LLM_MODEL_NAME`이 보인다.

**다르면** `docker compose logs embed`를 본다. 모델이 임베딩 모델로 인식되지 않으면 `.env`에 `EMBED_EXTRA_ARGS=--convert embed`를 주고 다시 올린다. 메모리 부족이면 `LLM_GPU_MEMORY`를 낮추거나 `LLM_MAX_MODEL_LEN`을 줄인다. 두 vLLM이 한 서버에 있으면 `LLM_GPU=0`, `EMBED_GPU=1`인지 본다.

### 3.3 앱 서버

```bash
docker compose --profile app up -d --wait
cd .. && python3 scripts/setup_openwebui.py
python3 scripts/load_scenario.py scenario/script.json
python3 scripts/demo_check.py scenario/script.json
```

**나와야 하는 것** 2.2에서 2.4와 같은 출력. 이번에는 `top-5 memories`가 `OK`여야 한다. `WARN`이 아니라 `FAIL`이면 그 질문의 기대 문구가 실제 임베더의 top-5에 없는 것이다.

**다르면** 기대 문구가 빠지면 대본을 고친다. 질문에 그 세션의 핵심 단어를 더 넣거나, 세션의 발화를 더 구체적으로 쓰거나, 기대 문구를 실제로 검색된 다른 문장으로 바꾼다. 고친 뒤 `load_scenario.py`와 `demo_check.py`를 다시 돌린다. 첫 적재가 500으로 실패하면 MemMachine 로그에서 임베딩 오류를 본다. `dimensions` 관련이면 `memmachine.yml`의 값이 모델과 다른 것이다.

### 3.4 화면과 시간

시연 장비의 `/etc/hosts`에 `deploy/hosts.example`의 줄을 넣은 뒤 브라우저로 `http://app:3000`(또는 앱 서버 IP)을 열고 2.5와 같이 본다. 스크립트는 `.env`의 IP를 쓰므로 `/etc/hosts`가 필요 없다. 대본 질문 넷을 차례로 보내고, 답이 시작되기까지의 시간과 왼쪽 목록이 뜨는 시간을 적는다. vLLM 로그(`docker compose logs llm`)에 `tools`가 들어간 요청이 없는지 본다. 있으면 세팅 도구의 항목이 없는 모델로 채팅한 것이므로 세팅 도구를 다시 실행하고, 부스 계정으로 들어가 두 모델만 쓴다(설계 5.3절).

### 3.5 결과 남기기

`docs/msr/ces2027_demo/verification_company_<날짜>.md`에 검사 출력, 화면 캡처, 걸린 시간, 고친 것을 적고 커밋한다. 틀은 [회사 실행서](company_runbook_2026-10-27.md) 8.1절에 있고, [Mac 검증](verification_mac_2026-10-27.md)과 같은 형식이다. 대본을 고쳤으면 `scenario/script.json`도 함께 커밋한다.

## 4. 자주 바꾸는 것

| 바꾸고 싶은 것 | 어디서 | 그 뒤에 할 일 |
|---|---|---|
| 검색 개수 k | 관리자 화면 Functions > MemMachine > Valves의 `TOP_K` | 없음. 다음 질문부터 적용 |
| 시연 날짜("Today is ...") | `.env`의 `DEMO_DATE` | `setup_openwebui.py` |
| 공통 시스템 프롬프트 | `.env`의 `BASE_SYSTEM_PROMPT` | `setup_openwebui.py` |
| 새 채팅을 임시 채팅으로 | `.env`의 `TEMPORARY_CHAT` | `setup_openwebui.py` |
| 새 채팅이 여는 쌍(즉시 또는 단계별) | `.env`의 `STEPS_BY_DEFAULT`(빈 값 또는 `true`) | 앱 서버 `docker compose --profile app up -d openwebui`(컨테이너만 다시 만든다), `demo_check.py` |
| 단계별 모델의 간격, 전달문 블록, 오른쪽의 같은 박자 | 관리자 화면 Functions > MemMachine > Valves의 `STEP_DELAY_MS`(기본 2000), `SHOW_PROMPT`, `PACE_NO_MEMORY` | 없음. 다음 질문부터 적용 |
| 화면에 보이는 기억 쪽 이름("MemMachine + 모델", "without MemMachine", 함수 제목) | `.env`의 `BRAND_NAME` | `setup_openwebui.py`. ID와 파일 이름은 그대로다 |
| 모델 옆 아바타 | `.env`의 `AVATAR_MEMORY`, `AVATAR_NO_MEMORY`(`assets/`의 PNG 이름 또는 절대 경로) | `setup_openwebui.py`, 브라우저 새로 고침 |
| 대본 | `scenario/script.json` | `load_scenario.py`, `demo_check.py` |
| 채팅 모델 | `.env`의 `LLM_MODEL_PATH`, `LLM_MODEL_NAME` | LLM 서버 다시 올리기, 앱 서버 `up -d openwebui`, `setup_openwebui.py`, `load_scenario.py`(과거 채팅에 적힌 모델 이름과 아바타도 새 모델로 바뀐다) |
| 임베딩 모델 | `.env`의 `EMBED_MODEL_PATH`, `memmachine.yml`의 `dimensions` | 임베더와 MemMachine 다시 올리기, `load_scenario.py` |
| 시연 중 관객 앞에서 기억 추가 | Valves의 `RECORD_MEMORY` 켜기, 새 채팅의 임시 채팅 단추 끄기, 왼쪽 모델만 선택해 대화, 끝나면 끄기 | 설계 부록 D. 끄는 것을 잊으면 검사 스크립트가 알려 준다 |

## 5. 문제 찾기

| 증상 | 원인 | 조치 |
|---|---|---|
| 무엇이 안 되는지 찾을 시간이 없다 | 무엇이든 | 그 서버에서 `scripts/demo_reset.sh <프로필>`을 실행한다(README "문제가 생겼을 때"). 그래도 안 되면 `--wipe`를 붙인다 |
| `sign-in failed ... HTTP 429` | 3분에 15번 넘게 로그인 | 3분 기다린다 |
| `this account is not an admin` | 첫 가입자가 다른 계정 | `down -v` 뒤 처음부터 |
| 왼쪽 카드에 `Memory search failed: ...` | MemMachine 또는 DB 연결 | `demo_check.py`의 앞부분 줄을 본다 |
| 왼쪽 카드에 `LLM call failed: HTTP 400 ...` | 프롬프트가 `LLM_MAX_MODEL_LEN`을 넘음 | 값을 늘리고 LLM 서버를 다시 올린다 |
| 모델 드롭다운에 `MemMachine pipe: cannot reach ...` | Pipe가 LLM 서버에 닿지 못함 | `.env`의 `LLM_HOST`와 LLM 서버 상태 |
| 오른쪽 답에 과거 정보가 들어감 | 두 모델 항목의 `builtin_tools` 차단이 풀림 | `setup_openwebui.py`를 다시 실행하고 vLLM 로그에서 `tools` 유무 확인 |
| 목록의 날짜와 사이드바의 시각이 하루 차이 | `.env`의 `TZ`가 시연 장비의 시간대와 다름 | `TZ`를 맞추고 `up -d openwebui` |
| 사이드바에 "in a month", 읽지 않음 점 | 대본 날짜가 오늘보다 미래 | 시연 날짜에는 정상. 2.5절 참고 |
| MemMachine 로그의 `No module named 'spacy'` | 쓰지 않는 retrieval agent의 선택 모듈 | 무시해도 된다 |
