> **두 개의 독립 발명축(모두 권리화 대상)**:
> - **축 A** — 낙폭과 위치를 **곱셈으로 결합**한 gap-anchored 컷(`gap × k^bias`). 기존과 동일하지 않음: Taguchi는 위치항 자체가 없고, CAR은 **덧셈**(`+i/N`)이라 무-낙폭 지점도 컷이 될 수 있는 반면, 본 방식은 낙폭이 0이면 위치와 무관하게 컷이 되지 않아 **항상 실제 낙폭에 앵커**됨 + 클러스터링 불필요 + 단일 연속 노브. (§6.1, §6.1.1)
> - **축 B** — 그 bias를 **자동 조절**하는 기능(점수분포 형상 / 예산 / 품질). (§6.2, 실시예 2~4)

## 3. 기술 분야

LLM 기반 AI 에이전트의 메모리/RAG 검색에서, 재순위화(reranking)된 후보 문맥 중 **답변 생성에 투입할 개수를 질의마다 동적으로 결정**하는 문맥 선택 기술. 벡터 DB·그래프 DB 기반 에이전트 메모리 서빙에 적용.

## 4. 배경기술

- RAG/에이전트 메모리는 통상 후보를 **고정 top-k** 개수로 자른다. k가 크면 토큰·연산·저장 IO 낭비와 노이즈 유입, k가 작으면 필요한 근거 누락(recall 저하)이 발생한다. 최적 k는 질의마다 다르지만 고정값은 이를 반영하지 못한다.
- **Adaptive-k** (Taguchi et al., "Efficient Context Selection for Long-Context QA: No Tuning, No Iteration, Just Adaptive-k", EMNLP 2025, arXiv:2506.08479): 점수 내림차순 정렬 후 **인접 점수 간 낙폭(gap)이 최대인 지점**에서 자른다. 학습·튜닝·반복 없이 질의별로 개수를 자동 결정한다. 그러나 **가장 큰 단일 낙폭 지점만** 보므로,
  - (a) 강한 reranker가 1위에 점수를 몰아주면 1~2개만 남기는 **과소선택**,
  - (b) 점수가 완만히 감소하는 **다중근거(multi-hop/집계) 질의**에서 근거 부족
  이 발생한다.
- **CAR** (Cluster-based Adaptive Retrieval, arXiv:2511.14769, 2025): 정규화 거리 클러스터링 + 낙폭·위치 복합 점수 `score_i = g_i / max_j g_j + i/N` 로 컷 지점을 정한다. 위치 항을 **덧셈**으로 반영하고 **클러스터 경계에서만** 평가하며, 별도 클러스터링(K-Means/DBSCAN/HDBSCAN) 단계가 필요하다.

## 5. 해결하고자 하는 과제

1. 낙폭 기반 컷의 **과소/과대 선택을 질의별로 자동 보정**한다.
2. **튜닝·학습·추가 지연 없이**, 이미 계산된 점수만으로 recall–비용(토큰/연산/IO) 균형을 자동 조절한다.
3. 기존 largest-gap 방식과 **하위호환**(특수 케이스로 환원)되는 단순 구조를 유지한다.

**[필수 구성]**

|---|---|---|---|

| 2 | 낙폭 산출부 | 인접 순위 간 낙폭 `g_k = s_k − s_(k+1)` 계산 | §6.1 |

### 6.1 기본형 — 위치 가중 낙폭 컷 (bias 도입)

점수 내림차순 `s_1 ≥ s_2 ≥ … ≥ s_n`, 낙폭 `g_k = s_k − s_{k+1}`.

- 기존(Adaptive-k): `k* = argmax_k g_k`
- **본 발명(기본형): `k* = argmax_k [ g_k · k^bias ]`, bias ≥ 0**

성질:
- `bias = 0 → k^0 = 1 →` 기존 largest-gap과 **완전 동일**(하위호환/안전 도입).
- `bias ↑ →` 후방(큰 k) 가중 ↑ → 더 많이 유지(recall ↑, 토큰 ↑). **bias는 recall–비용 트레이드오프의 단일 노브**.
- 위치 함수 `f(k)`는 단조증가면 일반화 가능(예: `k^bias`, `1 + bias·log k`, `1 + bias·k/n`).
- **곱셈형**이라 낙폭이 0에 가까운 지점은 위치가중과 무관하게 억제 → "의미 없는 후방 컷" 방지. (CAR의 덧셈형과 구조적으로 다름.)

**실시예 1 (MemMachine에 구현됨) — 고정 bias 컷 함수:**

```python
def adaptive_k_cutoff(scores_desc, min_k, max_k, bias=0.0) -> int:
    n = len(scores_desc)
    min_k = max(1, min_k)
    if n <= min_k:
        return n
    upper = min(max_k, n) if max_k > 0 else n
    last = min(upper, n - 1)          # 버려질 항목이 하나라도 남는 최대 컷
    best_k = upper
    best_score = -1.0
    for k in range(min_k, last + 1):
        gap = scores_desc[k - 1] - scores_desc[k]
        weighted = gap * (k ** bias)   # 핵심: 낙폭 × 위치가중
        if weighted > best_score:
            best_score = weighted
            best_k = k
    return best_k
```

#### 6.1.1 기본형(bias)의 신규성 논거 — "기존과 동일하지 않음"

본 기본형은 아래 세 가지 **구조적** 특징으로 선행기술과 구분된다(→ 명세서에서 진보성 논거로 전면 배치).

1. **위치의 곱셈 결합 → 컷이 항상 낙폭에 앵커(gap-anchored)**: `score_k = g_k · k^bias`. 낙폭 `g_k ≈ 0`이면 위치가 아무리 커도 `score_k ≈ 0` → **무-낙폭 지점은 절대 컷으로 선택되지 않음**. 컷은 언제나 "실제 존재하는 낙폭" 위에서만 일어나고, 위치는 여러 실제 낙폭들 사이의 **재가중**만 한다.
   - 대조 — **CAR은 덧셈형** `정규화낙폭 + i/N`: 위치항이 낙폭과 독립적으로 더해져, 낙폭이 작은 지점도 위치만으로 점수를 얻음 → 컷이 실제 낙폭에 앵커된다는 **구조적 보장이 없음**(클러스터 경계 제한으로 사후 완화). **Taguchi는 위치항 자체가 없음**(`argmax g_k`).
2. **클러스터링 불필요 · 전체 k 평가**: CAR은 K-Means/DBSCAN/HDBSCAN + silhouette grid search로 후보 경계집합 S를 먼저 만들어 그 위에서만 평가. 본 방식은 **모든 k를 그대로 평가**(추가 군집화·하이퍼파라미터 탐색 없음, 결정론적, 지연 ≈ 0).
3. **단일 연속 튜닝 노브(bias)**: CAR의 위치 가중은 `i/N` **고정**(강도 조절 불가). 본 방식은 연속 지수 `bias`로 위치 강도를 매끄럽게 이동 → recall–비용을 연속 제어, 그리고 이 노브가 **축 B(자동 조절)의 제어 대상**이 됨.

**비동치(non-equivalence) 수치 예 — 곱셈형이 덧셈형으로 도달할 수 없는 컷을 낸다:**

- 낙폭 `g = [0.50, 0, 0, 0.05]` (항목 5개, k=1..4). 실제 낙폭은 k=1(0.50)과 k=4(0.05) 둘뿐.
- **본 방식(곱셈)** `g·k^bias`:
  - `bias=0` → `[0.50, 0, 0, 0.05]` → **컷 k=1** (1개 유지)
  - `bias=2` → `[0.50, 0, 0, 0.05·16=0.80]` → **컷 k=4** (4개 유지)
- **CAR형(덧셈)** `정규화낙폭 + i/N` (정규화 max=0.50 → `[1, 0, 0, 0.1]`, `i/4=[.25,.5,.75,1.0]`) = `[1.25, 0.5, 0.75, 1.10]` → **컷 k=1** (1개)
- → **동일 입력에서 본 방식(bias=2)은 4개, CAR형은 1개.** 곱셈 지수는 후방의 작은 낙폭을 초기 큰 낙폭 위로 끌어올릴 수 있으나, 덧셈형은 위치항 상한(≤1) 때문에 불가능. **두 방식은 동치가 아니며, CAR은 이 결정에 도달할 튜닝 수단도 없다.**

### 6.2 자동 바이어스 조절 (본 발명의 차별적 핵심)

기본형의 `bias`를 사람이 고정하지 않고 **자동으로 설정**한다. 세 가지 실시예(단독 또는 조합).

#### 실시예 2 — 점수분포 형상 기반 질의별 자동 bias (무라벨·무지연) **[주 실시예]**

핵심 아이디어: **낙폭 분포의 "분리도(separability)"가 높을수록(뚜렷한 절벽) bias를 낮추고, 낮을수록(완만·모호) bias를 높인다.**
→ 절벽이 뚜렷하면 그 절벽을 신뢰해 타이트하게 자르고(≈기존 adaptive-k), 모호하면 더 많이 남겨 recall을 확보.

- 분리도 지표(예): 최대낙폭 대비 2위낙폭(또는 평균낙폭)의 비
  `R = g_(1) / (g_(2) + ε)`   (`g_(1)`=최대낙폭, `g_(2)`=2위 낙폭)
- 매핑(예): `bias = β_max · clip( 1 − (R − 1)/(R_0 − 1), 0, 1 )`  또는  `bias = β_max · exp( −(R − 1)/τ )`
  - `R` 큼(뚜렷한 절벽) → `bias → 0`
  - `R ≈ 1`(모호) → `bias → β_max`
- **이미 계산된 gap만 사용** → 추가 지연 ≈ 0, 라벨·학습 불필요. 질의별 자동.

#### 실시예 3 — 목표 예산 추종 폐루프 자동 bias (세션/코퍼스 단위)

목표 평균 유지개수 `K*`(또는 토큰예산 `T*`)를 두고, 최근 윈도우의 평균 유지개수 `K̄`를 EWMA로 추정한 뒤 비례제어로 bias를 갱신한다.

```
K̄ ← (1−α)·K̄ + α·(직전 질의 유지개수)
bias ← clip( bias + η·(K* − K̄), 0, β_max )     # K̄ < K* 이면 bias↑ → 더 유지
```

질의 분포·코퍼스 드리프트에 따라 bias가 자동으로 예산에 수렴. 운영자는 "개수"가 아니라 "목표 예산"만 지정.

#### 실시예 4 — 다운스트림 품질 피드백 자동 bias (온라인/밴딧)

생성 단계의 품질 신호를 보상으로 삼아 bias를 온라인 조절한다.
- 보상 신호(예): 답변의 **근거 인용률**(retrieved passage 실제 사용 비율), 검증기/LLM-judge 점수, 자기일관성, 사용자 피드백.
- 규칙: 근거부족 신호(낮은 인용률·낮은 확신) → `bias ↑`; 문맥 낭비 신호(대량 미사용) → `bias ↓`.
- 무-그래디언트 온라인 업데이트(연속 밴딧/AIMD)로 **토큰당 품질**을 최대화.

### 6.3 적용 범위

- 후보 점수는 **reranker 점수 또는 벡터 유사도** 무엇이든 가능. **vector DB·graph DB 혼합 풀**에 적용.
- 컷으로 투입 문맥량 ↓ → 생성단계 토큰·연산 및 저장/입출력(IO) 부하 ↓ → **자원 제약 환경(에이전트 메모리 서빙, 온디바이스)**에 유리.

### 6.4 추가 실시예 (변형례 — 설계우회 대비)

기본 골격(정렬 → 낙폭 → 위치가중 곱셈 → argmax 컷, 및 bias 자동조절)은 유지한 채 아래 축들로 변형 가능하다. 각 변형은 단독 또는 조합으로 실시된다.

**실시예 5 — 위치 가중 함수 f(k)의 변형 (곱셈 결합·gap-anchored 유지).**
컷 점수를 `g_k · f(k)`로 두되 `f(k)`를 순위 k에 대해 **단조증가하는 임의 함수**로 일반화:
- `f(k)=k^bias`(기본), `1 + bias·log k`, `1 + bias·(k/n)`, `exp(bias·k/n)`, 구간별 상수/룩업테이블 등.
- 공통 성질: 낙폭과 **곱셈** 결합 → 무-낙폭 지점 배제(§6.1.1) 유지, 단일 강도 파라미터(bias)로 조절.

**실시예 6 — 낙폭(gap) 정의의 변형.**
- (a) **상대 낙폭**: `(s_k − s_{k+1})/s_k` 또는 로그비 `log(s_k/s_{k+1})` → 점수 스케일 불변.
- (b) **윈도우 낙폭**: `s_k − s_{k+w}` (w≥1) → 평탄부·동점 구간에 강건. 특히 이웃 문맥 확장(expand_context)으로 인접 항목이 같은 점수를 물려받아 낙폭이 뭉개지는 경우에 대응.
- (c) **변환 점수 위 낙폭**: softmax·z-score·순위정규화 후 낙폭 산출.
- (d) **2차 차분(곡률)** 기반 컷.

**실시예 7 — 점수 소스의 변형.**
reranker 점수 / 벡터 유사도(cosine) / 하이브리드(리랭커+벡터+최신성 가중합) / 그래프 DB의 거리·중심성 / LLM 관련도 판정 확률 — **어느 점수든** 정렬·낙폭·가중을 동일 적용.

**실시예 8 — 자동 bias 구동 신호의 추가 변형** (§6.2 실시예 2~4 외).
- (a) **질의 유형 기반**: 단일근거 vs 다중근거(multi-hop/집계)를 경량 분류기 또는 질의 길이·개체 수로 판정 → 다중근거면 bias↑.
- (b) **신뢰도(점수 크기) 기반**: 최상위 점수 절대값이 낮으면(약한 검색) bias↑로 헤지, 높으면 bias↓.
- (c) **분포 엔트로피 기반**: 점수/낙폭 분포의 엔트로피가 높을수록 bias↑ (실시예 2의 분리도 지표 대체).
- (d) **컨텍스트 예산 인지**: LLM 잔여 컨텍스트 토큰에 맞춰 bias 상한을 동적 설정.

**실시예 9 — 선택 규칙의 변형.**
argmax 대신: (a) **임계값** — 가중 낙폭이 임계 초과 시점까지 유지; (b) **누적 점수질량**(top-p식); (c) **min_k/max_k 하드 가드** 결합; (d) 복수 컷 후보 생성 후 다운스트림이 선택.

**실시예 10 — 적용·통합 변형.**
- (a) **메모리 스코프별 bias**: session / long-term / procedural 메모리에 상이한 bias.
- (b) **멀티 에이전트**: 공유 메모리 vs 개인 메모리에 상이한 bias.
- (c) **expand_context 처리**: 이웃 항목이 핵심 에피소드 점수를 상속하는 경우, 확장 전 점수로 낙폭을 산출하거나 상속 점수를 낙폭 계산에서 제외.
- (d) **모달리티별 bias**: 텍스트 / 코드 / 표 청크에 별도 bias.

**실시예 11 — 학습형 자동 bias.**
- (a) **오프라인 학습 매핑**: (질의·점수 분포 특징) → bias 를 회귀/소형 MLP로 dev셋(recall·토큰 라벨) 학습.
- (b) **컨텍스트 밴딧/RL**: 풍부한 특징 기반 온라인 학습(실시예 4 확장).
- (c) **사용자·도메인별 bias 프로파일** 축적·적응.

## 7. 실시예: 수치 예 (예시이며 벤치마크 결과 아님)

**예1 — 뚜렷한 절벽**: 점수 `[0.95, 0.60, 0.58, 0.55, 0.52]`
- `gap = [0.35, 0.02, 0.03, 0.03]`. 고정 bias 0/1/2 → 유지 **1 / 1 / 4** 개.
- 분리도 `R = 0.35/0.03 ≈ 11.7`(매우 큼) → **자동 bias ≈ 0 → 유지 1개** (절벽 신뢰, 토큰 절약).

**예2 — 완만·모호**: 점수 `[0.80, 0.72, 0.65, 0.58, 0.50]`
- `gap = [0.08, 0.07, 0.07, 0.08]`. 분리도 `R = 0.08/0.08 ≈ 1` → **자동 bias ≈ β_max(=2)**
  → `gap·k² = [0.08, 0.28, 0.63, 1.28]` → **유지 4개** (recall 확보).

→ **동일 알고리즘이 점수 형상만으로** 절벽형은 1개, 완만형은 4개를 자동 선택.

## 8. 발명의 효과

- **무학습·무라벨·무반복**, 추가 지연 ≈ 0(이미 계산된 gap 재사용).
- **하위호환**(`bias=0` = 기존 adaptive-k) → 리스크 없는 점진 도입.
- 질의별 **recall–토큰/IO 균형 자동 최적화**: 쉬운 질의는 토큰 절약, 어려운(다중근거) 질의는 근거 확보.
- **media/DB 비종속**(점수 리스트에만 의존) → 벡터/그래프/온디바이스 등 확장.

## 9. 청구 포인트(안)

두 개의 독립항(축 A / 축 B)과 종속항으로 구성.

**[축 A — 위치 가중 낙폭 컷] (독립)**
1. 관련도 점수로 정렬된 후보들의 인접 낙폭 `g_k`에 **순위 k에 대해 단조증가하는 위치 가중 `f(k)`를 곱한** 값 `g_k·f(k)`를 최대화하는 지점에서 잘라 유지 개수를 정하는 문맥 선택 방법. *(위치항 없는 Taguchi, 덧셈형 CAR과 구분)*
2. 제1항에서 `f(k)=k^bias`, `bias>0`인 것. *(bias=0=largest-gap은 청구에서 제외 → Taguchi 회피)*
3. 제1항에서 낙폭과 위치를 **곱셈 결합**하여, 낙폭이 실질적으로 0인 지점은 위치와 무관하게 선택되지 않는(컷이 항상 실제 낙폭에 앵커되는) 것. *(덧셈형 CAR과 구분)*
4. 제1항의 평가가 **군집화 없이 모든 k**에 대해 수행되는 것.

**[축 B — 자동 bias 조절] (독립)**
5. 제1~4항의 `bias`를 **점수 분포의 분리도 지표에 반비례**하도록 질의별로 자동 설정하는 것.
6. 제5항에서 분리도 지표가 최대낙폭 대 (평균 또는 2위)낙폭의 비인 것.
7. 목표 유지개수/토큰예산을 추종하도록 **윈도우 통계 기반 폐루프**로 bias를 조절하는 것.
8. 다운스트림 **품질 보상**(인용률/검증점수/피드백)으로 bias를 온라인 조절하는 것.

**[적용]**
9. 제1~8항을 vector DB/graph DB 후보를 reranker로 채점한 **에이전트 메모리 검색**에 적용하는 것.

## 10. 선행기술 대비 차별성

| 항목 | Taguchi Adaptive-k | CAR | **본 발명** |
|---|---|---|---|
| 위치 반영 | 없음 | 있음 | 있음 |
| 낙폭·위치 결합 | — | **덧셈** `+i/N` | **곱셈** `×k^bias` |
| 컷의 낙폭 앵커(무-낙폭 지점 배제) | (항상, 위치無) | 구조적 보장 없음* | **항상 앵커** |
| 후보 평가 범위 | 전체 k | 클러스터 경계만 | 전체 k |
| 클러스터링 | 불필요 | **필요** | 불필요 |
| 위치강도 튜닝 노브 | — | 고정 `i/N` | **연속 `bias`** |
| bias 자동조절 | — | — | **분포형상·예산·품질** |
| 하위호환 | (기준) | 아님 | `bias=0`에서 동일 |
| 추가 지연 | 낮음 | 클러스터링 비용 | ≈ 0 |

(*CAR은 클러스터 경계 제한으로 사후 완화)

## 11. 공개 여부 / 유의사항 ⚠

1. **공개 이력 점검(최우선)**: 기본형(`gap·k^bias`, 고정 bias)은 **MemMachine 코드베이스에 이미 구현**됨(브랜치 `v0.3.9_msr`). MemMachine은 오픈소스 저장소이므로, 해당 코드가 **공개 저장소에 push/공개되었는지 반드시 확인**할 것. 공개되었다면 신규성 상실(공지) 위험이 있으므로 출원 전략(우선일 확보 여부)을 IP팀과 즉시 협의.
2. **두 축 모두 권리화**: 축 A(bias)와 축 B(자동조절) 모두 청구. 축 A의 진보성은 **①곱셈·gap-anchored ②군집화 불필요·전체 k ③연속 튜닝 노브**의 세 구조적 차이에 근거하며, §6.1.1 **비동치 예**를 진보성 논거로 전면 배치할 것. 단, CAR이 2025년 매우 최신 선행기술이라 "낙폭+위치 결합"에 대한 심사관 견제가 예상됨 → 청구는 **곱셈·gap-anchored 한정**을 명확히 하여 덧셈형과 차별화.
3. **bias=0 회피 드래프팅**: `bias=0`(=largest-gap)은 Taguchi로 신규성 부정 가능 → 독립항은 **`bias>0`** 또는 **"순위에 단조증가하는 위치 가중"**으로 한정(청구 제2항). `bias=0` 하위호환은 명세서 효과로만 기술하고 청구에는 넣지 않음.
4. **효과 입증**: recall↑·토큰↓ 효과는 정량 실험(예: LongMemEval)으로 뒷받침 권고. §7·§6.1.1 수치는 동작 예시이며 벤치마크 결과가 아님.
5. **선행기술 조사 범위**: 위 신규성은 별도 검색 필요. Taguchi·CAR 외에 **위치/순위 가중 선택, knee/elbow 검출(Kneedle), gap statistic(Tibshirani), 임계·변화점 검출** 계열까지 포함하여 조사할 것(곱셈 gap-anchored 프레이밍이 차별점). 본 문서는 신규성/특허성을 보증하지 않음.
